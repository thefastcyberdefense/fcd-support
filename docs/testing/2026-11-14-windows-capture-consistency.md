### Localized Loss-of-Proof Mechanisms Fixed

1. **Bounded auto-capture observer lifecycle under short caller budgets (`tests/helpers/process-lifecycle.ts` [`L100-L127`](../../tests/helpers/process-lifecycle.ts#L100-L127), [`L317-L399`](../../tests/helpers/process-lifecycle.ts#L317-L399), [`L596-L605`](../../tests/helpers/process-lifecycle.ts#L596-L605), [`L1562-L1575`](../../tests/helpers/process-lifecycle.ts#L1562-L1575), [`L1648-L1653`](../../tests/helpers/process-lifecycle.ts#L1648-L1653), [`L1690-L1691`](../../tests/helpers/process-lifecycle.ts#L1690-L1691))**: Background ownership capture spawned alongside `runBoundedCommand`, `waitForBarrier`, and `waitForExit` retains `AUTO_CAPTURE_MIN_TIMEOUT_MS = 1200` so short barrier waits (`~300 ms`) do not truncate WMI observation, while `startAutoOwnershipCapture(child, timeoutMs, maxCallerBudgetMs?)`, `ActiveCaptureControl.clampDeadline`, and `AbortController` ensure `reapChildProcess` clamps the capture deadline to `overallDeadline`, aborts in-flight `execBounded` (`proc.kill('SIGKILL')`) and `awaitAbortable` waits on budget expiration, and aborts `activeCaptureControls` in `finally`.
2. **Coherent `t1 -> t2 -> t3` recycled-WinPID non-adoption (`tests/helpers/process-lifecycle.ts` [`L711-L826`](../../tests/helpers/process-lifecycle.ts#L711-L826))**: In `captureProcessTreeOwnership`, when an initial MSYS pass (`t1`) sees a candidate WinPID absent from WMI and targeted follow-up WMI (`t2`) returns a row for that WinPID, `confirmMsys` runs a confirming post-WMI MSYS snapshot (`t3`) instead of blindly adopting the WMI row. Adoption is allowed only when `!rootAnchorFailed`, live MSYS anchors (`liveAnchorMsysPids`, `liveAnchorGroupKeys`) remain intact, the candidate passes `sameMsysIdentity`, and parent `CreationUs` / `liveWmi.creationUs >= rootCreationUs` invariants hold; post-WMI MSYS failures, exited roots, and recycled replacement MSYS identities never enter `ownedWinNodes`.
3. **Closed-root overlap, live-root single filtered WMI, and batched prefetch recovery (`tests/helpers/process-lifecycle.ts` [`L1000-L1242`](../../tests/helpers/process-lifecycle.ts#L1000-L1242))**: `inspectAndOptionallyReapWinTree` overlaps closed-root MSYS and filtered WMI calls via `Promise.all` (and batches unqueried prefetched WMI child PIDs whenever `missingFilterPids` requires a follow-up query so multi-level subshells do not add an extra sequential frontier WMI round), reads MSYS before single-batch filtered WMI on older live roots (`canReuseRecentWmiWindow` gated strictly), and restricts `liveWmi === undefined` PGID poisoning to `!queriedWmiPidSet.has(row.winPid)` so already-queried exited transients never block owned `-<pgid>` termination.
4. **Complete recursive Win32 frontier expansion and confirmed post-kill exit (`tests/helpers/process-lifecycle.ts` [`L990-L1473`](../../tests/helpers/process-lifecycle.ts#L990-L1473))**: Removed the ungrounded `observedMsysWinPids` fast-exit shortcut. `inspectAndOptionallyReapWinTree` runs `recomputeVerifiedTree()` ([`L1254-L1367`](../../tests/helpers/process-lifecycle.ts#L1254-L1367)) and loops ([`L1371-L1406`](../../tests/helpers/process-lifecycle.ts#L1371-L1406)) querying `unqueriedVerifiedPids` via `winOps.readWmiSnapshot(remainingMs(deadlineMs), unqueriedVerifiedPids)` until convergence—returning `false` (`test_child_reap_unconfirmed`) immediately without killing ancestors if the budget expires or any frontier query fails (`!frontierWmi.ok`). Verified WinPIDs are killed deepest-first (`computeDepth`, [`L1424-L1443`](../../tests/helpers/process-lifecycle.ts#L1424-L1443)) alongside verified MSYS PIDs/PGIDs, followed by post-kill verification (`performKill = false`, [`L1464-L1473`](../../tests/helpers/process-lifecycle.ts#L1464-L1473)).

## Remaining Limitations

- Windows process-tree inspection still invokes external `ps.exe` (`~114–187 ms`) and `cscript.exe` WMI (`~273–420 ms` filtered, up to `~563 ms` under peak contention; `~435–627 ms` unfiltered), leaving an inherent OS process-spawn floor inside shared `1,000 ms` reap budgets. In a four-worker synthetic stress probe spawning a late two-level non-MSYS native subtree after initial capture (`sleep 1.4` followed by `node -> node`), sequential recursive frontier queries plus post-kill native confirmation (`~1,019–1,038 ms`) still exceed `1,000 ms`, failing closed (`test_child_reap_unconfirmed`) rather than falsely reporting cleanup. No universal four-worker reliability guarantee for arbitrarily deep late-spawned native trees is claimed without Win32 Job Objects or FFI (out of scope here and subject to separate architecture/dependency review).
- Unrelated `tests/health-stdio-docker-harness.test.ts` ledger cleanup spawns multiple sequential `node.exe` mock-docker processes inside a `3,500 ms` `waitForExit` window and exceeded `3,500 ms` during intermediate competing/saturated runs before passing cleanly in both the isolated four-worker targeted run (`3,343 ms` test / `14.26s` file) and full run (`13.16s` file); it remains untouched as out of scope.
