# Phase 6 Failure Matrix Gap Map

## 1. Executive Summary & Purpose

This document provides a comprehensive, auditable requirement-to-test map for Phase 6 Task 15 in `fcd-support`. It audits every failure mode, outage scenario, and lifecycle boundary specified in the approved operational plan (`docs/superpowers/plans/2026-10-04-phase-6-hardened-local-operations.md`) and focused closeout specification (`docs/superpowers/plans/2026-10-31-phase-6-task-15-focused-closeout.md`).

To preserve documentation integrity and strict separation of duties, this map distinguishes four distinct evidentiary statuses:

1. **Covered**: Present and verified by existing automated tests (unit, native bash script, hermetic fake, or PostgreSQL integration).
2. **Confirmed Task 15 Gap**: An identified missing assertion or test scenario to be implemented locally by AGY in Task 15 (test-first: RED -> GREEN).
3. **Codex-Owned Server Check**: Actions and verifications that require live server access, SSH execution, synthetic server deployment, or independent launch gate sign-off (owned exclusively by Codex).
4. **Deferred P7/P8 Live Evidence**: Requirements explicitly deferred to Phase 7 or Phase 8 (e.g., live Meta Graph API / WhatsApp coexistence onboarding, live Manifest provider credentials, live n8n webhook routing, full physical host reboot).

## 3. Explicit Gap Inventory for Task 15

The audit previously identified the following three concrete gaps for local implementation under Task 15. All three have now been implemented, verified through their owning boundaries, and closed:

1. **Read-Only Backup Destination Failure (`EROFS`)**:
   - _Target file:_ `tests/backup.test.ts`.
   - _Resolution:_ Implemented with a dedicated Linux kernel read-only mount (`real read-only filesystem mount (EROFS) refuses backup write and leaves existing archives intact`), paired with a writable control and captured emitted output. Directory mode 0500 permission admission retained under accurate name (`directory with mode 0500 refuses admission before backup write`); injected publish error retained (`injected publish failure (EROFS) cleans partial files and preserves existing archives`); native tmpfs `ENOSPC` proof retained at `tests/backup.test.ts#L522-L545`.

2. **Restored Outbox Blind Resend Protection**:
   - _Target file:_ `tests/integration/postgres-outbound-flow.test.ts`.
   - _Resolution:_ Implemented in `tests/integration/postgres-outbound-flow.test.ts#L844-L1024` with an explicit older-snapshot divergence (provider acceptance ledger ahead of PostgreSQL snapshot), a single synthetic provider instance with captured send count across held and eligible-control runs, an unfenced synthetic PostgreSQL database fixture sending exactly once, repeated worker runs sending zero times, and active recovery hold preserved on the restored fixture without lifting.

3. **Scheduled Operation Lock Concurrency Barrier**:
   - _Target file:_ `tests/systemd-contract.test.ts` and `tests/integration/postgres-encrypted-backup.test.ts`.
   - _Resolution:_ Implemented with real `operations_scheduled_main` and `operations_preflight` nonblocking `flock` execution on `deployment.lock` with a deterministic barrier and clean bounded child reaping in `tests/systemd-contract.test.ts#L477-L623`, plus PostgreSQL catalog slot deduplication and zero duplicate dumps in `tests/integration/postgres-encrypted-backup.test.ts#L280-L295`, `#L450-L475`.
