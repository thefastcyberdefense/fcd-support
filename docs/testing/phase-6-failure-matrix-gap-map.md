# Phase 6 Failure Matrix Gap Map

## 1. Executive Summary & Purpose

This document provides a comprehensive, auditable requirement-to-test map for Phase 6 Task 15 in `fcd-support`. It audits every failure mode, outage scenario, and lifecycle boundary specified in the approved operational plan (`docs/superpowers/plans/2026-10-04-phase-6-hardened-local-operations.md`) and focused closeout specification (`docs/superpowers/plans/2026-10-31-phase-6-task-15-focused-closeout.md`).

To preserve documentation integrity and strict separation of duties, this map distinguishes four distinct evidentiary statuses:

1. **Covered**: Present and verified by existing automated tests (unit, native bash script, hermetic fake, or PostgreSQL integration).
2. **Confirmed Task 15 Gap**: An identified missing assertion or test scenario to be implemented locally by AGY in Task 15 (test-first: RED -> GREEN).
3. **Codex-Owned Server Check**: Actions and verifications that require live server access, SSH execution, synthetic server deployment, or independent launch gate sign-off (owned exclusively by Codex).
4. **Deferred P7/P8 Live Evidence**: Requirements explicitly deferred to Phase 7 or Phase 8 (e.g., live Meta Graph API / WhatsApp coexistence onboarding, live Manifest provider credentials, live n8n webhook routing, full physical host reboot).

## 3. Explicit Gap Inventory for Task 15

The audit identifies the following three concrete gaps for local implementation under Task 15:

1. **Read-Only Backup Destination Failure (`EROFS`)**:
   - *Target file:* `tests/backup.test.ts`.
   - *Requirement:* Write a test using an actual guarded read-only filesystem destination, with a successful writable control. Assert failure produces no successful catalog/manifest publication, preserves a previously valid authenticated archive, and leaves no newly owned partial ciphertext or temporary plaintext. Assert the closed error and absence of synthetic sensitive sentinels in captured output.
   - *Coverage distinction:* The Linux `ENOSPC` proof (`full tmpfs archive destination cleans ENOSPC partial ciphertext`) already exists in `tests/backup.test.ts#L352-L370`.

2. **Restored Outbox Blind Resend Protection**:
   - *Target file:* `tests/integration/postgres-outbound-flow.test.ts`.
   - *Requirement:* Compose the real isolated-restore/recovery fence (`PostgresRestoreFence`) with the owning outbox worker (`OutboundWorker`) and an injected synthetic provider against PostgreSQL. Exercise accepted work and the ambiguous older-snapshot case; assert zero provider send calls while inherited work is quarantined or recovery-held. A same-provider successful eligible control must send once. Repeated worker activation must not create a resend or clear a hold.

3. **Scheduled Operation Lock Concurrency Barrier**:
   - *Target file:* `tests/systemd-contract.test.ts` (or `tests/operations-scheduled-lock.test.ts`).
   - *Requirement:* Use two real Unix processes and the actual nonblocking flock boundary against one protected synthetic scope. Prove the first activation owns the lock and the second refuses without entering any job. Use a deterministic barrier rather than a guessed sleep. After release, prove a later eligible activation can run and a repeated current slot is deduplicated through the actual owning operation/catalog boundary.
