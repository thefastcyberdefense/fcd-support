## PR 22: blocking ownership regressions

### P1: stale MSYS relationships adopt a recycled unrelated WinPID

At `tests/helpers/process-lifecycle.ts:589–598`, a follow-up WMI query adds
new CreationDate values to the earlier MSYS parent/group relationships. It
checks root liveness before the await but does not establish coherent current
ownership after it. An unresolved child can exit and its WinPID can be reused
by an unrelated process during that query. The replacement is then recorded as
owned through stale MSYS ancestry and subsequently signaled.

An authored memory-only probe against the two exact Git blobs confirms:

| Revision            | Unrelated identity captured | Unrelated identity signaled |
| ------------------- | --------------------------- | --------------------------- |
| Base `94c9542`      | false                       | false                       |
| Submitted `fc5bfd8` | true                        | true                        |

All signal ports are fakes; no actual process identity is used. Re-observation
must prove current identity/ancestry or a live captured group anchor, or fail
closed. Merely testing root liveness once more does not prove that a reused
child still belongs to the captured tree.

### P1: filtered WMI misses a native grandchild and falsely confirms cleanup

At `tests/helpers/process-lifecycle.ts:941`, the older live-tree path now uses
a filtered WMI query rather than the prior unfiltered observation. The VBS
query matches the requested PIDs and their direct children. A native child and
native grandchild born after capture can have no MSYS rows. The grandchild
therefore escapes discovery, yet cleanup reports success after killing the
root and direct child. The `rootStillRunning` branch under prefetch cannot fix
this route: prefetch now occurs for a closed root.

The same frozen-base/head probe confirms:

| Revision            | Native child remains | Native grandchild remains | Cleanup result |
| ------------------- | -------------------- | ------------------------- | -------------- |
| Base `94c9542`      | false                | false                     | resolved       |
| Submitted `fc5bfd8` | false                | true                      | resolved       |

Recursive discovery/confirmation must be complete within the existing deadline,
or return `test_child_reap_unconfirmed`; a one-generation absence is not tree
exit proof. Do not fix this by accepting unknown ownership or killing ancestors
before the required descendant evidence is gathered.
